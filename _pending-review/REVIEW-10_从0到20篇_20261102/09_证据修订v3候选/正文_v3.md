# 一个人做内容，怎样让下一次不用从头开始

做内容能不能积累下来，要看下一次能否接着已有的材料做，而不是每次重新找素材、重新解释目标、重新核对状态。

这个月，我一直在整理自己的内容工作流程。到月底回看，值得写下来的除了稿件，还有几个容易被忽略的问题：计划和实发混在一起，旧建议比新决定更容易被找到，工具执行成功却不代表任务完成。

这篇复盘把这些问题拆开，给出一套一个人也能维护的办法：材料有入口，决定有出处，任务有验收，中断之后能接上。

## 1. 先把“准备过”与“做成了”分开

整理这篇复盘时，旧稿标题里有“20篇”。回头看计算方式，发现它来自计划档期和批量成稿安排。

这个数字能说明当时准备怎样生产，不能直接说明实际发表了多少。

我重新检查了一份本地统计快照。按其中的日期和状态字段筛选，可以得到19条有效的10月记录。但它采集于10月30日凌晨，覆盖范围也不完整，不能拿来当整个月的发表总数。

最容易犯的错误，是觉得原来的数字不可靠，便找一个新数字替上去。看起来严谨了，统计单位却还是没对齐。

因此，这次我撤下标题里的篇数。以后记录内容状态，至少分清四件事：已有正文、已建草稿、已安排发表、取得正式发表凭证。每一步保留对应证据，不能相互替代。

它听起来只是几列状态，却决定了下次会不会重复制作、会不会把待办误报成成果。

## 2. 素材先有入口，不急着全部读完

我手里的材料包括技术实践、学习笔记、选题卡、文章草稿和发布包。真正麻烦的地方，是开始任务时不知道该从哪份文件读起。

这次接管，我没有把整个知识库重新总结一遍，而是增加了一个恢复索引。索引只回答几个问题：事实在哪，最新决定在哪，当前任务在哪，执行记录在哪。

文章内容仍留在原发布包，排期仍查原台账，原始材料也留在原处。索引负责指路。

用 GitHub 管版本时，也要区分“能找到文件”和“文件内容仍然有效”。一个旧操作单可能写着尚未发表，但新统计里已经有同题文章。先看状态证据，再决定是否继续制作。

素材多时，先把入口做清楚，比每次让 AI 把全部材料重新读一遍更容易检查。

## 3. 新决定要能盖过旧建议

长会话里，方案经常会变。

讨论广告时，早先可能建议关闭多个位置，后来又决定只关闭文章中部广告。如果只在聊天末尾说一句“按新的来”，换个会话后，旧建议仍可能被当成操作依据。

我的处理方式是保留历史，在原事实页增加明确的覆盖说明：哪个决定有效，旧建议从什么时候失效，为什么调整。

排期也一样。正文文件名、包内操作单、月份草案可能各写一个日期。谁更新得晚只是线索，还要看它记录的是建议、用户确认，还是后台实际状态。

所以，一条重要决定至少写清楚三项：内容是什么，依据在哪里，当前处于什么状态。这样新来的 Agent 才有机会复现判断，而不是碰巧读到某一版就照做。

## 4. 检查要落在读者真正会遇到的问题上

我仍然会检查格式、隐私和合规，但这些检查通过，不等于文章已经可靠。

一篇稿子可能没有格式错误，却把旧报价当现价，把示意比例写成统计结果，或者给一个没有找到来源的故事加上“我亲眼见过”。这些问题不能靠加粗数量检查出来。

因此，我把审查分成两层。

一层查形式：段落是否过长，引用是否清楚，敏感信息是否残留，正文和图片的标题是否一致。

另一层查事实：数字的单位和时间是什么，故事能否找到原始记录，因果结论有没有越过证据，示例有没有冒充实测。

AI 可以帮助列出疑点，但疑点成立与否仍要回到材料上。一个人发现的严重事实错误也应处理，不能等另一个角色同意才算问题。

遇到证据缺口，选择也不只有补资料。非必要的数字可以撤掉，虚构风险高的故事可以改成明确标注的示例，不影响主题的争议细节可以暂时不写。

## 5. 中断之前，留下能接着做的记录

这次恢复工作里，一个实际教训是：产物做出来了，方向仍可能错。

我本来想继续推进文章，Agent却沿着历史候选制作了贴图。文字检查通过了，也有文件了，但它没有满足我当前的意图。

这件事提醒我，任务验收要同时检查结果和方向。不能只问文件是否存在，还要问它是否解决了这次的问题。

现在，我希望每个阶段结束时留下几行可以核对的记录：实际读取了什么，检查了什么，结果如何，哪些地方没验证，下一步准备解决什么。

AGENTS.md负责边界与导航，Skill负责可复用做法，SDD负责本次需求、计划和验收。执行日志再补上这次真正发生的事情，避免把“流程里应该做”写成“已经做过”。

换模型、换工具或结束聊天时，接手者先读这些记录，再按问题回到原材料。能否恢复正确状态，需要实际验证；文件齐全只是开始。

## 6. 下一次开工，可以先做这三件事

先找一个入口，把当前任务会用到的材料连起来。不要为了整齐复制出另一套知识库。

再给重要状态补证据。稿件、排期、发表分开；数字写上单位、范围和截止时间；最新决定标明它覆盖了什么。

最后留一个恢复点。写清已经完成的部分、仍然缺的证据，以及下一步的具体动作。不要只写“继续优化”。

这些做法不保证写得更快，也不能代替选题判断。但下一次开始时，我能先检查已有积累，再决定还需要做什么。

我做公众号的初衷，是留下能展示、能核实、能复用的作品，让同行知道我解决过什么问题。文章数量只是其中一种记录。更值得维护的，是这些作品背后的判断、证据和可以接着做的工作。
