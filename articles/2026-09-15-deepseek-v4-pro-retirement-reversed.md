# DeepSeek V4 Pro 不下线了：一场没完成的退役，和三个通用判断

> 一句话摘要：原定 9 月 14 日 12:00 下线的 DeepSeek V4 Pro，在「死线」当天被官方按住了——继续提供 API 服务，计费方式不变。两天三个版本，这场没完成的退役，比退役本身更值得看。

【配图：00-引子_官方公告.png】

这篇原本是冲着「V4 Pro 9 月 14 日下线」写的——我连迁移账都算好了，就等那天发。结果发布前夜官方掉头：继续提供、计费不变。所以我也想知道答案：一个被用户按住不退的旗舰，到底说明什么？下面是我带着同样的问题，拆出来的三张账和一个判断。

先说结论：V4 Pro 不下线了。9 月 14 日当天，DeepSeek 在开放平台挂出公告——「为响应广大用户的需求，我们决定在 9 月 14 日之后继续提供 V4 Pro 的 API 调用服务，计费方式保持不变」。如果你昨天已经在改迁移预案，可以先放下了；但这三天里发生的事，比「下不下线」本身更值得每个用 API 的人看一遍。

注意最后那句「计费方式保持不变」——它意味着现在有两条路都通：留在 V4 Pro，按原旗舰价继续用；或者主动迁到 V4.1-Flash，吃新价。强制切换取消了，选择题回来了。

## 为什么用户不让下线

官方原话是「响应广大用户的需求」。我的解读，底层是三笔账：

1. 存量生产依赖。改模型名从来不是改一行字符串——监控、告警、回归测试、灰度验证，一整套都要重来。官方说「性能追平」，那是在官方测试集上追平；生产环境的用户不敢拿自己的业务替官方做验证。
2. 「追平」是测试口径，不是生产共识，还得按场景看。短中篇中文写作，Flash 实测几乎追平——散文文风迁移评测拿了 91.3 分，部分测试套件的写作得分还略胜 Pro；可一到十万字级长篇，它就把「扫地扫到第几遍」记乱了（3 亿 token 实测）。降价能改变账单，改变不了已经稳定运行的生产环境。谨慎的用户宁可多付钱，也不在没跑满回归的情况下切换——这部分真金白银的需求，正是 V4 Pro 被按住的原因。
3. 对官方，砍旗舰伤的是信任。企业客户刚把核心业务押在旗舰上，旗舰说砍就砍，下一次选型时人家就会掂量。Flash 架构本身推理成本不高，继续服务的代价，远小于信任的代价。

这也是对上一篇「斩杀线」逻辑的一次重要修正：**斩杀线管的是价格，管不了信任。价格追平，不等于心智追平。**

补一句群里追问最多的「广大用户到底是谁」——多半是中文识别与内容创作这类任务：它们对单次质量敏感、对 token 成本不敏感，正好落在 Flash 一时追不平的那一格。

## 并发账：Flash 侧的隐性利好

并发上限从 500 提到 2500，五倍——这是 Flash 路线的隐性筹码。对跑批量任务和多 Agent 并行的团队，排队等额度的隐性成本，降价解决不了，提并发解决。模型侧的底气也摆在这：它的总参数有 552B（B 就是 Billion，十亿），但每处理一个词只唤醒其中 8B——这叫稀疏激活，像一家 552 人的公司，接一个活只叫 8 个人上，所以又快又省钱。缓存同样被压到了原来的四分之一，办法是换用更「瘦」的数字格式来存（FP4）：位数少一半，占的显存和读取量就少一半，同一张卡能装下更多东西；代价是精度会掉，所以关键层仍然留着高精度混着用——PEC 大会上有嘉宾提到，V4 用的就是 FP4/FP6 混合精度。至于 Terminal-Bench 4.0 从 7.0 涨到 31.2，那是一项考 Agent 在真实终端里干活的基准测试（装环境、改配置、跑命令这一路），分数翻了四倍多，说的是它「自己动手」的能力。

把「低精度」这件事换算一下就知道多要紧：1B 参数，用 FP16 存要 2GB、FP8 是 1GB、FP4 只要 0.5GB——552B 这么个大家伙，FP16 得吃掉 1.1TB 显存，换 FP4 立刻降到 276GB。「跑不动的巨兽」和「用得起的旗舰」之间，差的就是这一次换算；而 276GB 依然很贵，所以还得靠稀疏激活每次只动用 8B（FP4 下约 4GB）把成本压下来。

那为什么不用更省心的 FP8？因为这两档不是一个量级的活儿。FP8 有 256 个刻度，相邻刻度差约 1/8，量化后效果几乎不掉，属于可以直接上；FP4 只剩 16 个刻度、相邻刻度最多能差一半，能表示的范围也窄得多——所以必须给每一小块数据单独配一个缩放比例来补偿，关键层还得拿 FP6 顶上。这就是「混合精度」为什么是混着的：**省下的显存，是用工程复杂度换的**。

但反过来想：官方宁可被用户按住也要推 Flash，说明这套架构的成本曲线足够陡——这次没完成的退役，大概率只是推迟，不是取消。V4.1 Pro 上线那天，这道选择题会重新发下来。

## 选型三查：现在该做什么

强制切换没了，主动决策来了。三件事检查一遍：

1. 生产敢不敢换：官方说追平不等于你的业务追平——用一两周做同任务对照回归，数据说话，别看发布会。
2. 账单结构：算你自己的缓存命中率（上面那张算术账可以直接照抄），命中率决定你迁过去省多少。
3. 并发配额：2500 的新上限能不能用满，取决于任务编排吃不吃得下并行度。

## 我的实测账本：先给一手片段，再等整周数据

原计划的「下线前后对照」作废了——既然不用切，就改测更有价值的那个问题：同一 Agent 工作流，V4 Pro 与 V4.1-Flash 同任务对照，记四个数：账单差额、缓存命中率、首 token 延迟、高峰时段费用占比。数据跑满一周才够诚实，先立框架不放拍脑袋的数。

但一手片段可以先交个底。这几轮降价，群里问我最多的一句是「真有省那么多吗」——我的答案是：真省，还不是一点。同样一份用量，走 Flash 比走 Pro 省 81%（5.3 倍），两个原因，缺一不可：

1. 模型选对了。光缓存未命中的输入单价就差 4.5 倍（1 元 vs 4.5 元）；
2. 命中率是隐藏开关。我这边缓存命中率 97.7%，绝大部分 token 走缓存读取，而缓存价只有新输入价的五十分之一（0.02 元 vs 1 元）。

一把账算给你看：同样一份用量，如果大部分是新输入，成本自然下不来；反过来，把命中率做上去，同一个业务能少花好几倍。这也是前一篇里那句话的意思——价格表是公开信息，命中率才是你自己的变量。

【配图：07-真实用量账单.png】

把账真正摊开：过去一个月（8/16–9/14），DeepSeek 系模型跑掉真实消耗 77.14 亿 tokens、2.8 万次请求，命中率 97.7%。按官方定价逐条算（含高峰 ×2）：Flash 路线 750 元，同样这份用量放在 Pro 上是 3,983 元——差 5.3 倍，一个月省下 3,233 元。

命中率才是那只手。同一份用量，命中率从 97.7% 掉到 90%，账单变 1,792 元；掉到 80% 是 3,144 元，4.2 倍；掉到 60% 直接 5,850 元。缓存不是省钱的技巧，它就是这套价格结构本身。

还有一笔白捡的：我这边 77% 的 token 落在高峰时段，同样的量全挪到空闲时段，750 元能降到 421 元——省 44%，一行代码没改。

怎么量出来？我用的是本地工具自带的使用统计——它记录每次请求的输入、输出、缓存读写与费用，按天聚合；平台侧的用量面板也能看个大概。办法不高级，但管用：先在客户端挂一层本地代理，跑满一周，再把输入、输出、缓存三项拉出来做除法。**先量出来，再决定迁不迁**，比看任何榜单都实在。

四个数齐了，「留 Pro 还是迁 Flash」对你就不是观点题，而是算术题。

不过说到底，命中率只解决「同样的活怎么更便宜」，解决不了「这些活该不该让模型干」。后者才是大头——我把它放在「省 token 系列」里单独讲，这篇先不展开。

## 群里问得最多的三个问题

这几轮模型换代，我在开发者群里被反复问的就三个，一并答了：

① 快速模型和高级模型，到底怎么选？
Flash 这类模型体积小、响应快，适合高频日常任务；Pro 的综合能力在长尾任务上更稳，代价是更贵也更慢。日常走 Flash、长尾和复杂约束留给 Pro——别用一把尺子量两个场景。

② 为什么有时候快、有时候慢？
大概率不是模型的问题，是通道的问题。如果你走的是第三方中转站，性能全看对方怎么调度；想稳定，直接连官方模型，走官方后付费或 token plan，再配个 `cc switch` 之类的工具切换。

③ 要不要上企业级订阅？
先别急着买，真正该看的是并发数，不是「企业版」三个字。一个官方账号的并发上限，已经够百人级团队用；企业版真正的价值，是 SLA、合规与发票、数据条款这些——你需要它们，就该买；你只是担心并发不够，那多半不必。

顺带一个容易踩的坑：官方文档里模型名要写 `deepseek-flash`。旧的 `deepseek-v4-flash` 这些名字还能调，但对应的模型已经下线，请求会自动由 V4.1-Flash 提供服务，并按 Flash 价格计费——名字还能用，账单已经换了。

## 谁该关心，谁可以不关心

关心的：已按迁移预案动手的团队（先停手，重新做选择题）、账单里输入占大头的应用（命中价降 87%，Flash 路线收益明确）、正在选型的团队（同价位段两条路都通，但要掂量「退役推迟」的信号）。

可以不关心的：个人轻度调用——你留在 Pro 还是随缘用 Flash，账单差距大概一杯奶茶的量。这也是这场反转里最轻松的一群人。

## 被按住的退役，说明什么

一个观察：DeepSeek 同期扩招约 150 人，方向包括 Agent 弹性计算与 Harness 工具；同一周，旗舰退役被用户按住。一边招人扩产能，一边为老用户掉头——后者不会写进任何路线图，但它比一场干干净净的退役更难得。

这个判断对不对，看 V4.1 Pro 上线那天。

## 比事件更值钱的：三个通用判断

把这件事排到一起，它给出了适用于以后每一次模型更迭的三个判断：

一、别问哪个模型强，问它在任务剖面的哪一格强。V4 Pro 开发长尾我们实测也就那样，写作却是全家最强，剩下的护城河只有十万字级一致性——榜单排名是横切的，你的需求是纵切的。

二、成本决策的单位是场景频次，不是模型。高频开发调用可以因成本禁掉，低频高价值的写作值得溢价——把它从高频场景里禁掉本身没有错，错的是平移到所有场景。

三、更迭的终局不是替换，是分层共存。旗舰和 Flash 各管一段，厂商愿意让旧型号活着，本身就说明它背后站着真需求——你的模型组合，也该是组合，不是单选。

## 核心结论

- V4 Pro 不下线了：9/14 官方宣布继续提供服务、计费方式不变，强制切换取消（平台公告+多源交叉核实）
- 三天三个版本：9/9 宣布切换 → 9/10 推迟 → 9/14 反转，罕见的公开掉头
- 现在是选择题：留 V4 Pro 原价，或迁 V4.1-Flash 新价（降约七到八成，高峰 ×2）
- 「追平」是测试口径不是生产共识——斩杀线管价格，管不了信任
- 迁移收益看你的缓存命中率：推演下命中率 0→80%，月账单 320→163 元
- 退役大概率推迟而非取消：V4.1 Pro 上线之日，选择题重新开考
