# FDE 获客成交交付操作手册（商业化现场版）v1.0

来源：`001-huangama-fde-from-zero-case.md` 拆解卡（黄啊码《从 0 到 1 做 FDE》自述复盘）的方法蒸馏，结合行途 2026-11-03 后端变现往 B 端靠拢的既定裁决改写为可执行清单。文中价格带为原作者客群口径，只作结构参照，行途对外报价须按自身客群与成本重算，不照抄数字。

## 一、接单前：先算 ROI，再谈签约

- 没算清投入产出之前不签合同，哪怕客户催签；无限改需求、无限延期、尾款被砍是技术出身者接单的典型死法。
- 每个机会先过商业模式定位：这单是完全定制（复用 0、不接或高价）、大客户定制（靠关系与背书，新手慎碰）、训练营型（培训业务骨干自己建工作流，按关键卡点收咨询费）、还是可复用模块型（底层复用目标 60%–80%，优先争取）。
- 前 5–10 个付费客户先跑通「调研 → 拆 SOP → 交付 → 收款」完整闭环，赛道收拢放在闭环之后。

## 二、场景筛选：红黑榜

可接（红榜）：
- 销售与获客增量场景：受益方是销售团队，省时直接换提成，利益一致、配合度高、零利益冲突；
- 内部经营风险管控：涉及岗位少，但单点年省金额大（原文量级为 200–300 万元级），老板付费爽快；
- 判断口径与案例集选流程三条件合并使用：每天重复、有人工结果可对照、报给老板本人看。

不接（黑榜）：
- 小体量行政/财务提效：盘子小（原文例：3–5 人团队顶天省约 60 万/年），还要动老员工饭碗，阻力大于价值；
- 通用型企业知识库：做完无法向老板证明多赚了多少钱，使用方也嫌麻烦，属高阻力、低价值；
- 一句话自检：这件事做成之后，老板能不能直接看见钱（多赚、少花、避险）？看不见就先放下。

## 三、获客：四条路径与询价处理

路径（按原文转化率排序，行途按自身条件取舍）：
1. 具象产品进垂直行业场合：带一个已跑通的行业痛点 Demo 去老板峰会、付费论坛做短拆解，不去全是同行的技术大会；
2. 枢纽人物：行业协会、商会等枢纽人物绑定合作，给明确返点，一次推荐顶多次陌拜；
3. 政府与园区公益背书：免费公益科普培训换「特邀讲师」身份，打开园区企业大门；
4. 公域实战输出：图文截图 + 录屏讲解决具体卡点的过程，不发纯代码教程；内容本身兼作获客漏斗。

询价三步漏斗（微信/私信收到「做个 XX 大概多少钱」时）：
1. 不直接报数字：统一回复口径——AI 落地与买软件不同，各家流程不同，不看现场直接报价，要么坑客户要么交付不了；
2. 立刻约线下：提出两个具体时间选项，请对方选，现场摸一遍业务流程再给评估；
3. 分流：死活不见面、只逼报价的，礼貌结束（多为基层比价任务或无预算询价）；爽快答应的，标记为准客户，现场同时核实对接人是不是老板本人或能拍板的高管。

## 四、报价：产品梯队与心理锚点

- 报价铁律：按客户业务体量、痛点严重程度、心理锚点定价，不按自身成本加成、不按人天工时明细报价；对方逼问物料与工时明细时，只报整体价值方案（防拿清单去比价）。
- 产品梯队结构参照（原文价格带，行途须重算）：诊断包（低价短周期破冰）→ 单点闭环灯塔项目（树立标杆）→ 部门级工作台（深度绑定）→ 年度陪跑包（按月、稳定现金流）。陪跑一页纸按此梯队改写。
- 人天底价自检公式：（原月薪 × 2）÷ 21.75，再乘 1.5 倍周期冗余；低于此线不接定制。
- 分档锚点话术：年营收 3000 万–5000 万级，算人头账（顶掉几个人力、省多少钱、第一年回本）；年营收 2 亿–5 亿以上级，算组织损耗与管理风险账（跨部门扯皮的延期成本），不纠结几万元人工费。
- 谈判四条：不说裁员说托底（把优秀员工经验沉淀为 SOP，新人入职与晋升可复用）；正式汇报定需求、非正式场域（饭局、茶室）定合作；先用诊断小包破冰建立信任，再谈大项目；陌生分包团队慎用，磨合与兜底成本常高于收益。

## 五、规模化：场景蒸馏与双轮驱动

- 蒸馏三步：抽离多客户共性，沉淀标准组件与行业 Prompt 库；保留 10%–20% 定制接口供新客户微调；报价转「模块接入费 + 年度订阅费」，目标是交付周期从一个月压到几天。
- 双轮配比：B 端每月保留 1–2 个高客单深度陪跑托底现金与背书；公域轻量产品（小课、社群、模板）做长尾收入，同时持续筛出下一批高意向客户。
- 窗口意识：驻场信息差的溢价会随模型原生化与企业数字基建成熟而收窄，跑通现金流后立刻产品化，不恋战人天模式。

## 六、交付技术底线（够用就好）

- 工具熟练度自检：会搭平台之外，必须过四关——状态管理、接口重试与降级、环境与依赖冲突处理、看得懂终端错误日志；过不了关不开工。
- 数据清洗三坑发前检查：标识符字段禁止隐式类型转换（如编号「0017」不得变 17）；同名字段先与业务方核对口径定义再合并；关联查询后计数要按业务主键去重，不按行数。
- Prompt 与上下文：流畅不等于正确，关键结论二次核验；token 按成本与延迟预算管理，不无脑塞长文；温度调低不替代兜底。
- RAG 排他原则：向量检索之前，先用业务元数据或 SQL 硬过滤，把型号、版本等不兼容切片物理隔离，再谈语义召回。
- 工作流编排：先确定性条件分支框死主干（原文口径约 80% 流程），只在模糊意图理解、多源文档提炼等单点挂轻量 Agent；能用规则解决的不给模型自由发挥。
