# 多模态评论数据清洗操作手册（FDE 现场版）

版本：v1.0，2026-10-28
来源案例：Miles Ma（@miles_mazy）《FDE 实战案例｜数据清洗》，X，2026-10-27，https://x.com/miles_mazy/status/2109456942822326325
用途：给未来的自己在 FDE 现场做评论/舆情类数据清洗时直接照着执行。标注「案例原文」的是原作者方法；标注「行途补充」的是结合本人电商与内容数据经验加的操作细节，执行时可按项目情况调整。

## 0. 总原则（四条，先背下来）

1. 原始层只读：源数据永不直接修改。先完整采集落盘，再在派生层做清洗。这样一份源数据可以被多个项目以不同口径反复调用，互不影响。（案例原文的方法 + 评论区一线从业者 Hanbin-AI 的补充，两者一致）
2. 口径先行：没定口径表之前，不开始清洗，更不开始建模。
3. 顺序固定：对齐 → 去重 → 噪音标记 → 语义归因。确定的、便宜的步骤先做；语义最贵、最容易被前置错误污染，放最后。
4. 证据回链：任何归纳结论必须能点回原话/原图/原录音。不能回溯的结论不交付。

## 1. 适用场景与输入输出

适用：舆情分析、竞品调研、营销活动复盘，以及一切以用户评论为原料的分析。
输入：多源、多模态、万条量级的原始反馈数据。
输出：一套可信数据集（结构化表 + 口径表 + 处理记录 + 抽检记录），供多个业务共用，不为单个业务单独洗一遍。

## 2. 阶段一：业务定义（半天内完成）

先回答三个问题，写下来给业务方确认：

- 谁用：舆情、竞品、复盘，分别是谁在看；
- 做什么决策：看完分析要改什么动作（选品、定价、活动节奏、话术）；
- 更新频率：一次性交付，还是按周/按活动批次滚动更新。

确认后冻结本期范围，新增需求走变更，不在清洗中途改口径。

## 3. 阶段二：定口径（六套表，清洗前必须齐）

### 3.1 产品别名表
字段：标准产品名 | 别名/简称/错别字写法 | 规格（容量、色号、版本） | 上市/停售时间 | 备注
要点：用户口语里的简称、主播带货时的叫法、旧版本名称都要收进来。

### 3.2 成分词表
字段：标准成分名 | 俗称 | 英文/INCI 名 | 用户常见误写 | 备注（争议成分单独标记）

### 3.3 肤质词表（按行业替换为本品类的人群词表）
字段：标准人群标签 | 用户原话说法示例 | 归并规则

### 3.4 价格口径
- 明确区分：日常价、活动价、券后价、直播间价，四者不得混列；
- 每条价格信息必须带口径标记和时间标记；
- 用户只说「贵/便宜」没给数字的，记感受，不反推具体价格。

### 3.5 渠道口径
字段：渠道标准名（社媒/电商/直播/客服/线下）| 平台 | 店铺/账号 | 归并规则

### 3.6 时间口径
- 以内容发布时间为准，采集时间单独记录；
- 活动批次先划好时间窗（如大促预热期、爆发期、返场期），后续噪音标记和复盘都依赖它。

## 4. 阶段三：采集与登记

数据源清单（案例原文六类，按项目删减）：社媒帖子、电商长评、「问大家」、直播弹幕与回放、客服记录、线下问卷与访谈。

每批数据登记一行：批次号 | 来源渠道 | 时间范围 | 条数 | 格式 | 原始文件存放位置 | 采集人 | 备注。
原始文件只读保存，不在原文件上做任何编辑。

## 5. 阶段四：统一字段结构（每条样本八字段）

| 字段 | 说明 |
|---|---|
| 产品 | 按产品别名表归一后的标准名 |
| 时间 | 发布时间（原始时间另存） |
| 渠道 | 按渠道口径归一 |
| 人群 | 按人群词表归一（如肤质） |
| 场景 | 使用场景（通勤、熬夜后、换季等） |
| 问题点 | 用户明确表达的不满或困惑 |
| 满意点 | 用户明确表达的认可 |
| 原话证据 | 原文摘录或原件链接，必填 |

附加标记字段：noise_type（噪音类型，可空）、activity_batch（活动批次）、weight（权重，默认 1，降权时调低）、dedup_group（去重组编号）。

分析维度（案例原文的五维框架）：功效、肤感、成分、价格、使用场景。八字段是落库结构，五维是分析时的归类框架，两者不要混。

拆解方法分工（案例原文）：规则和词表托底，处理确定性匹配；模型处理长尾表达和上下文；人工抽检兜底。不允许只靠关键词，也不允许模型无词表自由发挥。

## 6. 阶段五：多模态处理细则

- 截图类（追评、晒单图、包装破损图）：OCR 提取文字入结构化表，图片原件留档，OCR 结果要抽检（行途补充：首批至少抽检 5%，错误率高就整批复核或换工具重跑）。
- 视频类（开箱、试用、教程）：抽帧取关键画面信息，ASR 转写口播，两路结果分开存、再合并到同一条样本。
- 直播弹幕：按时间窗口聚合（行途补充：窗口大小按直播节奏定，先用 1 分钟试聚合再调整），统计情绪与关键词密度，不逐条生成评论样本。
- 问卷与访谈：保留原录音/原卷，转写后逐段与原文对齐编号，引用时可回溯到段落。

## 7. 阶段六：按固定顺序清洗

### 步骤 1：时间对齐、产品对齐
按时间口径和别名表，把所有样本先落到统一的时间轴和产品名上。这一步没做完，不许进下一步。

### 步骤 2：去重（三层）
1. 完全重复：文本完全一致，直接合并，保留来源记录；
2. 模板变体：同一模板改几个字的，归为同组；
3. 同义重复表达：意思相同、说法不同的，归组标记。
红线：同一用户在不同渠道的真实复购评价不得当重复误杀——先看用户与购买证据，再决定是否合并。合并后在 dedup_group 里留组编号，处理可回溯。

另注意：同一人在多个平台重复表达要能识别（跨平台同人识别），避免一个人的多次表达在统计里变成多人共识。

### 步骤 3：营销噪音标记（不删除）
三类动作：标记来源、标记疑似模板、标记活动批次，然后降权（调 weight），不删除。
原因：营销密度本身是业务信号，删了就丢了活动复盘要用的信息；标记降权后，舆情分析可以排除它，复盘分析可以专门看它。

### 步骤 4：情感与语义归因（最后做）
在干净样本上跑情感判断和五维归因。归因结果必须带原话证据字段，抽检不合格就回炉调规则/词表，不直接改结果。

## 8. 阶段七：验收（五条，全过才算交付）

1. 字段标准统一：随机抽样检查八字段填写规范；
2. 证据可追溯：任抽一条结论，能点回原话/原件；
3. 来源可解释：每批样本来源、时间范围说得清；
4. 处理有记录：重复与营销样本的合并、降权都有日志；
5. 业务方能抽样复核：把抽样包（样本 + 口径表 + 处理记录）交给业务方，复核通过并留记录，才算交付完成。

任何一条不过，回到对应阶段返工，不在结果表上手改数字。

## 9. 交付物清单

- 可信数据集（结构化表，含八字段与全部标记字段）；
- 六套口径表（本期版本）；
- 清洗处理记录（去重、降权、合并日志）；
- 多模态处理记录（OCR/ASR 批次与抽检结果）；
- 业务方抽样复核记录。

## 10. 常见坑（按踩坑代价排序）

1. 活动价和日常价混列——价格维度的所有分析作废；
2. 先做情感分析再对齐产品——归因对象都是错的，越分析越偏；
3. 去重只按文本全等——模板变体和同义重复全漏，样本量虚高；
4. 误杀真实复购评价——把最高价值样本当垃圾删了；
5. 营销样本直接删除——活动复盘失去关键信号；
6. 弹幕逐条当评论分析——把情绪流当评价，结论失真；
7. 结论没有原话证据——业务方无法复核，数据再干净也不敢用；
8. 每个业务各洗一遍——口径必然打架，三个报表三个数。

## 附：一页速查

定口径（六表）→ 采集登记（原始只读）→ 八字段拆解（规则托底、模型长尾、人工抽检）→ 多模态分开洗（OCR / 抽帧+ASR / 弹幕聚合 / 访谈对齐）→ 对齐 → 去重三层 → 噪音标记降权 → 语义归因 → 五条验收 → 交付五件套。
